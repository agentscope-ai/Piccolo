# 泰拉瑞亚种子地图版本

前端与 RL 共用 `web/playground/terraria-core.js`，地图参数统一由 `world-seed.js` 的 `terramaiLayout(seed, options)` 生成。模型仍选择探索、采矿、升级、战斗等意图，原有执行器完成操作。地图生成不调用规划求解器、不替模型执行胜利路线。

## 新地图

新建环境默认使用 `terramai-map-v2-diverse`。种子改变实际地表高度和坡度、地表坑、悬台、洞穴数量、树木密度、矿石密度、宝箱/熔岩/毒雾/食物数量，以及初始普通敌人的位置、类型和数量。保持 240 × 100 地图大小，底部基岩不变，出生点及 Boss/门附近提供有效地面和必要头顶空间。

旧地图已有随种子变化的随机地形、洞穴和矿石，但生成规模较固定；本次增加数量和布局参数的自由度。`foothills`、`caverns`、`ravines` 是生成类型，不修改胜利定义。仍须由玩家击败守门 Boss 才能开门通关；Boss 等级、战斗物理、死亡、重生、成长和奖励计算未改变。

64 个测试种子产生 64 张唯一实际地图、64 种主地形和 64 个唯一公开初始观测。实测坑数 2–8、悬台数 2–7、洞穴生成数量 20–48、地图矿石格数 200–674、初始普通敌人数 0–5。配置数量是生成请求；受树木、洞穴和有效站位限制，实际宝箱和普通敌人数可能更少，记录实际结果。

## 历史重放

`reset(seed, {generator_revision: 'world-seed-v1'})` 使用原版生成分支和随机调用顺序。修改前保存的 5 个种子完整公开快照、完整私有地图及渲染状态与此分支严格一致。调用 `reset(seed)` 使用新版本；非法种子或版本在修改当前动作和状态前拒绝。

前端与 Node 环境均支持上述参数。新 RL episode 在模型输入外的 `environment_generation` 回执记录 `seed`、`generator_revision`、`profile`。重放根据回执选择生成版本；历史 Terra episode 缺少该字段时固定使用 `world-seed-v1`，不悄悄切成新图。

生成版本、种子、完整地表数组、全图资源分布和未探索敌人布局不进入 `snapshot()` 或模型 TrainingRecord。模型继续只看到已探索的局部地图及已观察记忆。

## 验证

`tests/terra_seeded_curriculum.py` 检查 64 种子的地图唯一性、同种子完整状态复现、地图边界、出生空间、守门 Boss/门锁、局部信息隔离、非法 reset 原子性，以及新图和旧图实际 Node 实时短局的严格重放。修改前完整状态对照通过 `JEV_TERRA_LEGACY_BASELINE` 指定不可修改的证据文件。

本次验收记录为 `terra-map-v2/acceptance.json`，由运行方保存在独立证据目录，不是可移植运行所需文件。短局控制器明确为 off-policy，仅验证调用链、真实时间推进及重放，不能作为学生或教师完整通关成绩。
