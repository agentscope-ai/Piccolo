## 并发延迟证据

停止本任务的 4 并发 rollout 后，对完全相同的三个真实游戏输入，分别运行 1、2、4 并发，各两批，共 42 次请求。下表为每档观测到的最大 HTTP 耗时；不是 p95 或延迟上限。

| 输入 | 1 并发 | 2 并发 | 4 并发 |
|---|---:|---:|---:|
| 2048 | 0.38 秒 | 0.43 秒 | 0.78 秒 |
| 贪吃蛇 | 0.47 秒 | 0.90 秒 | 1.72 秒 |
| 五子棋 | 2.99 秒 | 5.96 秒 | 11.92 秒 |

长输入并发耗时接近线性增长，支持服务串行处理、其他请求排队的判断。原记录中的十几秒是端到端耗时，不能等同于单次模型推理时间。服务未提供独立推理计时，无法精确拆出 GPU 计算与服务端排队时间。完整原始记录：`data/playground-debug-20261021/latency-comparison.json`。

## 修复行为

- 请求并发默认 1，页面“请求选项”可显式调整；浏览器与后端均执行相同限制。重复 request ID 在进入队列之前拒绝，换代后的连接仍不能执行旧请求。
- 交互试玩每动作调用模型一次，沿用原候选顺序；不伪造稳定性指标。正式 Arena 评测与离线完整对局脚本继续采用原三次顺序探测，实时游戏仍为一次，保持历史评测口径。
- 传输保留有限的错误类别：鉴权、限流、超时、错误端点、不可用服务与无效响应。重复判断异常保留安全的 cause，页面显示可操作的中文/英文提示，不再显示原始异常 JSON。
- 交互式贪吃蛇、俄罗斯方块、赛车及注册实时游戏不因一次 API 失败而人工设为负局。真实物理时钟继续；自然碰撞、超时等原生终局仍有效。连接恢复后可重试，也可继续手动操作。正式评测的基础设施错误统计规则未改。
- System One 桥接默认串行，对断连等传输失败做有界重试；不重试协议校验失败，不用规则动作替代模型。客户端超时立即上报，避免串行积累多轮超时。
- 2048 手机端使用完整正方形棋盘，不再横向裁切。画布文字继承全站字体；游戏控件、卡片、结果与错误提示沿用站点纸色与暖色边框，主要触控按钮不小于 44 像素。
- 中国象棋等 DOM 棋盘复用棋盘节点；同状态返回页面时保留当前棋盘与选中状态，避免重建导致焦点和交互丢失。私有手牌交接仍需显式点击揭示，不绕过隐私流程。
